TSConfig

tsconfig.json — это конфигурационный файл TypeScript-проекта; он говорит компилятору, IDE и другим инструментам (например, линтер и сборщик), какие файлы считать частью проекта и как их проверять и компилировать.

Compiler Options​

{
  "target": "ES2025",
  "lib": ["ES2025", "DOM", "DOM.Iterable"],
  "strict": true,
  "erasableSyntaxOnly": true,
}

Целевая платформа и окружение​

  • target – определяет версию стандарта ECMAScript, которая будет использована компилятором при генерации JavaScript; значением может быть конкретный стандарт, например,ES2025, либо специальное значение ESNext – самая высокая поддерживаемая версия

  • lib – определяет множество встроенных JavaScript API и их типы, которые компилятор считает доступными: ECMAScript API, DOM API, Web Worker и другое; опция не влияет на генерируемый код, она влияет только на этап проверки типов

  • allowJs – позволяет компилятору обрабатывать JavaScript-файлы как часть программы; по умолчанию для таких файлов проверка типов отключена, чтобы это исправить используется опция checkJs

  • erasableSyntaxOnly – гарантирует, что TypeScript-код останется валидным JavaScript после простого удаления всех типовых аннотаций; запрещает enum, namespace, parameter properties и некоторые устаревшие конструкции

Модули​

  • module – определяет целевую систему модулей сгенерированного JavaScript
  • moduleDetection – управляет критерием различения модулей и скриптов
  • moduleResolution – управляет стратегей поиска и разрешения импортов
  • resolveJsonModule – позволяет импортировать JSON-файлы как модули
  • paths – позволяет создавать псевдонимы для путей
  • verbatimModuleSyntax – обязательная аннотация импортов типов
  • allowImportingTsExtensions – разрешает расширения .ts и .tsx в импортах
  • isolatedModules – проверка на безопасную сборку модулей по отдельности
  • noUncheckedSideEffectImports – проверка импортов ради побочного эффекта

Статический анализ кода​

  • strict – включает полный набор строгих проверок типов
  • strictNullChecks – требует явно учитывать null и undefined при проверке типов
  • strictFunctionTypes – включает строгую проверку совместимости типов параметров функций
  • strictBindCallApply – проверяет корректность аргументов методов bind, call и apply
  • strictPropertyInitialization – требует инициализировать все свойства класса при объявлении или в конструкторе, если они не допускают undefined
  • noImplicitAny – запрещает компилятору неявно присваивать тип any, требуя явно указывать тип в такой ситуации
  • noImplicitThis – вызывает ошибку, если тип this в функции не указан явно и не может быть выведен
  • noImplicitReturns – требует, чтобы все логические пути в функции, которая возвращает значение, явно заканчивались оператором return
  • noImplicitOverride – требует помечать override методы или свойства, переопределяющие члены базового класса
  • noUncheckedIndexedAccess – добавляет undefined к типу, получаемому при доступе по индексу
  • noFallthroughCasesInSwitch – вызывает ошибку, если в блоке switch есть непустой case, который "проваливается" в следующий
  • useUnknownInCatchVariables – типизирует переменную в блоке catch как unknown вместо any

Разделение​

  • tsconfig.json — точка входа
  • tsconfig.app.json — конфигурация основного приложения
  • tsconfig.node.json — конфигурация кода для Node.js
tsconfig.json
{
  "files": [],
  "references": [
    {"path": "./tsconfig.app.json"},
    {"path": "./tsconfig.node.json"}
  ]
}
tsconfig.app.json
{
  "compilerOptions": {...}, // options for application
  "include": ["src"]
}
tsconfig.node.json
{
  "compilerOptions": {...}, // options for Node.js
  "include": ["vite.config.ts", "scripts"]
}
